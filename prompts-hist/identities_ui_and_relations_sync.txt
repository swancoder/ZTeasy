Deviations from literal task wording (see the ADR for full reasoning):

- System-client filtering happens inside KeycloakIdpAdapter.fetchClients()
  itself (a .filter() on the reactive stream before mapping to IdpIdentity),
  not as a UI-side hide — these clients are never synced or cached at all,
  not synced-then-hidden. isSystemClient(...) made package-visible+static
  specifically so it gets a direct unit test (this adapter's other fetchX()
  methods have never had one, proven only by IdentitySyncIT against a real
  Keycloak since ADR-014 — kept that precedent, added the one piece that's
  actually pure/testable in isolation).
- IdpIdentityRepository.upsert's existing @Query gained a RETURNING id
  clause and its return type changed from Mono<Void> to Mono<UUID> —
  IdentitySyncService needs the (possibly pre-existing, possibly
  freshly-generated) internal PK back to resolve relations' subject/target
  columns without a second lookup query per identity. Source-compatible for
  every existing caller (they already discarded the Mono<Void> value).
  Also removed the now-unneeded @Modifying annotation — that switches
  Spring Data R2DBC's result handling to "read affected-row-count," which
  is wrong for a RETURNING clause that needs its result set mapped to UUID.
- fetchRelations() resolves a client's role assignments via its
  *service-account user* (a separate Keycloak entity via
  GET /clients/{id}/service-account-user), not the client itself — Keycloak
  stores client role-mappings there, not on the client resource. Reports
  the relation against the client's own external id regardless (not the
  service-account user's), since idp_identities never caches service-account
  users as their own USER row (confirmed live in the ADR-014 session that
  Keycloak's /users endpoint already excludes them). A client without
  serviceAccountsEnabled 404s on that lookup — caught with onErrorResume
  per client, not failing the whole sync, mirroring OrphanedRuleChecker's
  established per-rule resilience pattern from the ADR-014 session's live
  Flyway/R2DBC race fix.
- IdentitySyncService.syncNow() now does two passes per cycle
  (syncIdentities() collects a Map<externalId, internalId> from the upsert
  RETURNING clause; syncRelations(map) resolves and upserts relations
  against that map) — zero extra DB round trips to resolve relation
  subject/target ids, since every relation names an entity the same
  cycle's identity fetch already named. An unresolvable relation (shouldn't
  happen, by that invariant) is logged and skipped, not a sync failure.
- UI: "info" icon uses a plain emoji glyph (ℹ️), not @mui/icons-material —
  this codebase has consistently avoided that dependency (PolicyDashboard's
  orphan-warning icon is also a bare emoji); kept the same convention rather
  than introducing a new icon library for one button.
- GROUP/ROLE accordions get no "info" button — the task's own Task 4 only
  asks for the icon on User/Client rows; the reverse direction ("which
  Actors have this Role/Group") is named as a Future Migration Path item,
  not silently built or silently skipped.
