Task: add an integration test for the MCP proxy flow.

Context: this was the highest-priority gap flagged in ADR-009 and
docs/SPEC.md §8.4/§9.3 — McpSessionManagerTest and DummyMcpPolicyEngineTest
(Stage 8) only cover those two components in isolation; nothing exercised the
actual cross-request session-injection mechanism (GET /sse -> POST /message
-> result written into the still-open SSE stream) against a real running
gateway.

Implementation: McpProxyIT (gateway-service/src/it), following the existing
BaseZteIntegrationTest/HappyPathIT/WireMock pattern from Stage 6. Wired
mcp-backend.uri to WireMock in BaseZteIntegrationTest alongside
service-a.uri/service-b.uri. Uses WebTestClient to open the SSE stream and
StepVerifier to interleave a blocking RestAssured POST /message between
assertNext expectations, since the emission into the session sink happens
synchronously (from the reactive pipeline's perspective) before the POST
returns 202. Three scenarios: denied tool call (backend never called, denial
injected), allowed tool call (forwarded to WireMock, result relayed), unknown
sessionId (400).
