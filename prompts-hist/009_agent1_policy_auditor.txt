==============================================================
CHAIN OF THOUGHT
==============================================================

Authentication for zt-agents → gateway:
  Gateway runs HTTP (not HTTPS), so transport mTLS to the gateway is infeasible
  without adding a second HTTPS listener. MVP uses network restriction (Docker bridge).
  InternalSecurityConfig (@Order -100) applies permitAll() for /api/v1/internal/**;
  ZteAuthorizationFilter passes unauthenticated requests through via defaultIfEmpty path.
  Production upgrade: Keycloak service account + client_credentials + INTERNAL role + DB policy.

Why internal REST endpoint (not direct DB):
  Service boundary must be maintained. Gateway owns the policy schema. Direct DB access
  from zt-agents would violate Zero Trust service isolation and couple schema to agent.

Why WebClient not Anthropic SDK:
  No official Java/Kotlin SDK. WebClient is already on classpath, returns Mono<T>,
  composes natively with the reactive pipeline. Full control over timeout, retries, headers.

Synchronous-reactive endpoint:
  Returns complete Mono<AuditReport> — no thread blocked while LLM responds.
  120-second timeout with WebFlux reactor Mono.timeout(). Streaming deferred.

Kotlin in Java build:
  Root build.gradle.kts applies `java` to all subprojects. zt-agents adds kotlin.jvm
  and kotlin.spring plugins locally. No interference with other modules.
